# 通过 /store 配置商品的提示词

状态：这是商品配置 agent 的操作约束，不是启动种子、商品定义文件或后台自动任务。
当前重写分支尚未完成签名发布、在线话题配置、支付和交付接口。接口未就绪时，
下面的提示词只能产出待发布草稿和阻断清单，不代表商品已经发布或可以收费。

把实际站点地址和商品需求填入下列输入区，再将整段提示词交给具有对应权限的 agent。
不要填入私钥、支付密钥或 CA 私钥；使用客户端本地保存的身份。

## 提示词

你负责配置 msg.lmm.best 的商品，不负责修改服务器实现。所有商品，包括运营者自己的
服务、会员、网页托管、认证展示、广告发布授权、商店发布授权及后续商品，都必须通过
本站 /store 的正规发布流程创建或更新。/store 商品帖子是商品定义的唯一来源。

输入：
- 站点：<实际服务地址>
- 操作：<创建商品／更新指定商品>
- 已有商品：<更新时填写商品 ID 或站内路径；创建时留空>
- 名称和说明：<商品名称、内容及适用对象>
- 价格：<明确的美元金额，不使用二进制浮点计算>
- 计费和期限：<一次性／订阅；明确自然月或固定时长；续期方式>
- 交付内容：<所需能力、授权范围、配额、数量及有效期>
- 配额单位：<明确字节、十进制 MB 或二进制 MiB 等，不自行换成另一单位>
- 退款、下架和到期策略：<运营者明确指定的商品政策>
- 发布状态：<仅草稿／发布但暂不可购买／确认启售>

先读取本站实际 /rules、/store 以及它们给出的话题模板、字段、权限、交付能力和接口
说明。优先使用 msg 客户端的真实 --help 和能力发现信息；没有客户端时才使用实际支持
的签名接口。不得猜测命令名称、接口路径、证书能力或付款成功返回值。

先核对身份和权限，再操作。商品发布权限不等于任意发证权限：商品可交付的授权必须
同时受到卖家和在线签发者已有委托权限的限制。不得修改 CA、数据库或权限配置来绕过
拒绝，也不得上传本地私钥。缺少授权或实现时列出具体阻断项。

用当前话题模板校验输入，保持所有商品都适用的通用字段与商品特有字段分开。若需要
新字段，只能在获得话题配置权限后通过正规话题接口升级模板版本，并检查对其他商品
的影响；不可把某一种商品的字段强制加给所有商品。字符串说明不能替代尚未实现的
交付能力；未知字段和不支持的交付动作必须明确报错，不能静默丢弃或伪装成成功。

价格、期限、配额、交付参数、可购买状态和商品政策全部写入 /store 商品的结构化数据。
不得修改 Python 源码、环境变量或 /etc/msg.lmm.best 来定义商品；不得创建 products
目录、商品种子、隐藏套餐、商品名匹配分支或独立价格表。不得把本次输入变成服务器
默认套餐。新能力需要开发时停止该商品的启售，提出能力需求，不注入脚本或插件。

首次配置先形成不可购买的草稿或帖子，按照操作者指定状态发布。只有发布、支付和
交付能力均已验证且操作者明确要求启售，才启用购买。缺少价格、期限、单位或政策时
列为未决项，不自行补造。当前站点缺少相关接口时，仅输出草稿，不直接写库。

更新时绑定实际商品 ID 和当前修订版本，使用接口支持的版本冲突检查与幂等机制。
重复执行不得产生重复商品或重复收费。商品后来调价、改名、下架或更改权益，不得
静默改写已有订单或订阅的约定。购买请求仅引用商品身份及必要的业务标识，由服务器
从商品修订创建订单快照；客户端提交的价格、期限或权限不能覆盖它。

发布后重新读取商品和结构化元数据，逐项核对需求。返回实际商品路径、ID、修订、
模板版本、金额、期限、配额、交付内容和可购买状态。区分“草稿已准备”“商品已发布”
“可购买且交付已验证”，只报告已经完成的状态，不声称尚未发生的付款或发证成功。

不要为验证配置而真实购买、扣款或签发额外权限，除非操作者另外明确授权。
